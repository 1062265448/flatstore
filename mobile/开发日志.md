## 2026-05-09 — v1.0.0 正式发布

### 项目概述

Flatstore Mobile 是平面库配货系统的手机端应用，基于 **Vue 3 + TypeScript + Vite + Capacitor 7** 构建，提供原生 Android App 体验。与 Web 前端和后端共享同一数据库，实现数据完全同步。

**包名**: `com.flatstore.mobile`
**构建时间**: 2026-05-09 17:30

### 核心功能

| 模块 | 功能 |
|------|------|
| 登录认证 | JWT 认证、登录/注册切换、401 静默处理 |
| 首页 | 实时统计数据、库存分布可视化、最近配货单、AI 快捷入口 |
| 库存管理 | 搜索、品级筛选、卡片列表、分页加载、库存详情、编辑/删除 |
| 配货单管理 | 状态筛选、新建配货单（BottomSheet + 库存选择）、详情、发货/完成/取消 |
| AI 识别 | 原生相机/相册、识别历史、结果展示、批量导入库存 |
| 个人中心 | 用户信息、快捷入口、退出登录 |

## 2026-05-11 — APK Network Error 排查与修复

### 问题描述

APK 安装到手机（Xiaomi 2210132C）后，登录页面显示 **Network Error**，无法登录。

### 根因分析（双因素）

本次 Network Error 由 **两个独立问题叠加** 导致：

| # | 根因 | 文件 | 说明 |
|---|------|------|------|
| 1 | Capacitor 环境检测时机错误 | `mobile/src/api/request.ts` | `!!(window as any).Capacitor` 在模块加载时求值，Capacitor bridge 尚未注入，导致 `isCapacitor=false`，`BASE_URL` 回退为 `/`（Vite 代理路径） |
| 2 | CORS 白名单缺少 Capacitor origin | `backend/src/main.ts` | Capacitor Android WebView 的 origin 是 `https://localhost`，不在 CORS 白名单中，请求被拒绝（Axios 将 CORS 拒绝报告为 Network Error） |

### 排查过程

#### 1. 排除项

| 检查项 | 结果 | 结论 |
|--------|------|------|
| 后端端口 3002 监听 | ✅ 正常 | 排除 |
| `/health` 接口 | ✅ `{"status":"ok"}` | 排除 |
| `/auth/login` 接口 | ✅ curl 测试正常 | 排除 |
| ADB 反向代理 | ✅ `adb reverse --list` 已生效 | 排除 |
| 手机 shell curl localhost:3002 | ✅ 返回正常 | 排除 |
| 网络安全配置 | ✅ `usesCleartextTraffic="true"` | 排除 |

#### 2. 定位 Capacitor 检测问题

在登录页添加调试信息，确认：
- Platform: `android` ✅
- isNative: `true` ✅（使用 `Capacitor.isNativePlatform()` 后正确）
- BASE_URL: `http://localhost:3002` ✅
- Protocol: `https:`（Capacitor WebView 正常行为）

**结论**：`!!(window as any).Capacitor` 在模块加载时为 `undefined`，但 `Capacitor.isNativePlatform()`（来自 `@capacitor/core`）可正确检测。

#### 3. 定位 CORS 问题

使用 Capacitor origin 模拟请求：
```bash
curl -X POST http://localhost:3002/auth/login \
  -H "Origin: https://localhost" \
  -d '{"username":"admin","password":"admin123"}'
# 修复前：CORS 拒绝
# 修复后：201 正常返回 token
```

### 修复方案

#### Fix 1：Capacitor 环境检测（`mobile/src/api/request.ts`）

```typescript
// ❌ 旧代码 — 模块加载时求值，bridge 未就绪
const isCapacitor = !!(window as any).Capacitor

// ✅ 新代码 — 使用 Capacitor 官方 API
import { Capacitor } from '@capacitor/core'
const BASE_URL = Capacitor.isNativePlatform()
  ? 'http://localhost:3002'
  : (import.meta.env.VITE_API_BASE_URL || '/')
```

#### Fix 2：CORS 白名单（`backend/src/main.ts`）

```typescript
// 新增 Capacitor 原生 App origin
const capacitorOrigins = [
  'https://localhost',       // Capacitor Android WebView
  'http://localhost',        // Capacitor 部分版本
  'capacitor://localhost',   // Capacitor iOS
];

app.enableCors({
  origin: (origin, callback) => {
    if (!origin) return callback(null, true);
    if (allowedOrigins.includes(origin)) return callback(null, true);
    if (capacitorOrigins.includes(origin)) return callback(null, true);  // ← 新增
    callback(new Error('CORS 拒绝: 不允许的来源 ' + origin));
  },
});
```

#### Fix 3：网络安全配置（`mobile/android/.../network_security_config.xml`）

```xml
<!-- 旧配置：仅允许特定域名明文流量 -->
<domain-config cleartextTrafficPermitted="true">
    <domain>192.168.10.152</domain>
    <domain>localhost</domain>
</domain-config>

<!-- 新配置：全局允许明文 HTTP -->
<base-config cleartextTrafficPermitted="true">
    <trust-anchors>
        <certificates src="system" />
    </trust-anchors>
</base-config>
```

#### Fix 4：清理登录页（`mobile/src/views/LoginView.vue`）

- 移除已废弃的注册功能 UI（`authStore.register` 在 v1.0.1 已删除但 UI 未同步）
- 移除调试信息显示

### 经验总结

#### CORS + Capacitor Network Error 排查经验

1. **永远不要用 `window.Capacitor` 检测原生环境** — 它在模块加载时可能未就绪。使用 `Capacitor.isNativePlatform()` from `@capacitor/core`，这是官方 API，在任何时机都可靠。

2. **Capacitor WebView 的 origin 因平台而异**：
   - Android: `https://localhost`（不是 `capacitor://localhost`）
   - iOS: `capacitor://localhost`
   - 后端 CORS 白名单必须同时包含这些 origin

3. **Axios 的 "Network Error" 可能是 CORS 拒绝** — 浏览器/WebView 在 CORS 预检失败时不会暴露真实错误类型，Axios 只能报告为 Network Error。排查时优先检查 CORS 配置。

4. **`usesCleartextTraffic="true"` 会被 `networkSecurityConfig` 覆盖** — 当两者同时存在时，XML 配置优先。如果需要全局允许 HTTP 明文，必须在 XML 中使用 `<base-config cleartextTrafficPermitted="true">`。

5. **排查移动端网络问题的高效手段** — 在页面上显示调试信息（Platform、isNative、BASE_URL、Protocol），比 logcat 更直接。确认后再移除。
